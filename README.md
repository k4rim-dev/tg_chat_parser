# Telegram Chat Parser

собирает HTML-экспорт Telegram в один файл. начинал с консольного скрипта, потом добавил окно, чтобы не прописывать пути руками. голосовые и кружки можно расшифровать через [faster-whisper](https://github.com/SYSTRAN/faster-whisper).

## запуск на Windows

нужен Python 3.12 с pip и Tcl/Tk либо [uv](https://docs.astral.sh/uv/).

1. скачай или клонируй репозиторий.
2. запусти `setup.bat`: он создаст `.venv` и установит зависимости.
3. запусти `start.bat`, выбери папку чата и файл для результата.
4. если нужна расшифровка, включи «Распознавать речь». затем нажми «Собрать переписку».

распознавание по умолчанию выключено. без него вместо речи остаются ссылки на медиа. для первой загрузки модели нужен интернет; дальше можно включить «Только скачанная модель».

## экспорт чата

в Telegram Desktop: меню нужного чата → экспорт истории чата → формат **HTML**. для расшифровки включи голосовые и видеосообщения. проверь период выгрузки и лимит размера файлов.

выбирай папку с `messages.html`, сохранив каталоги медиа рядом. если страниц несколько, парсер сам прочитает `messages2.html`, `messages3.html` и т. д. ZIP и JSON-экспорт Telegram на входе не поддерживаются.

## установка вручную

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-audio.txt
.venv\Scripts\python parser.py
```

если расшифровка не нужна, достаточно `requirements.txt`. в Linux/macOS используй `python3 -m venv .venv` и `.venv/bin/python`; Tk может потребовать отдельного пакета, например `python3-tk` в Ubuntu. основной код требует Python 3.10+, для аудиозависимостей рекомендую 3.12.

## через консоль

```powershell
.venv\Scripts\python parser.py "C:\Exports\ChatExport"
.venv\Scripts\python parser.py "C:\Exports\ChatExport" -o "C:\Exports\chat.md" --transcribe --model small --language ru
.venv\Scripts\python parser.py "C:\Exports\ChatExport" -o "C:\Exports\chat.json" --transcribe --offline
.venv\Scripts\python parser.py --help
```

без аргументов открывается окно. вместо папки можно передать `messages.html`, но прочитаны будут все страницы рядом. без `-o` результат сохраняется в `full_chat.txt` внутри экспорта. для замены существующего файла нужен `--overwrite`.

модели: `tiny`, `base`, `small`, `medium`, `large-v3`. по умолчанию `small`, CPU, int8. `tiny` и `base` быстрее, большие модели требуют больше памяти и времени. язык: `ru` по умолчанию, `auto` для автоопределения или другой код языка Whisper.

## результат

сохраняются отправители, даты, текст с переносами, ответы, реакции и отметки о вложениях. служебные события вроде вступления в чат пропускаются. повторные ID сообщений не дублируются.

пример на вымышленных сообщениях:

```text
[19.11.2026 12:00:00 UTC+03:00] Аня: Привет! Как проект?
[19.11.2026 12:01:00 UTC+03:00] Борис (ответ на: «Привет! Как проект?»): [ГС: Сегодня допишу интерфейс.]
```

- `.txt`: обычный текст;
- `.md`: Markdown с экранированием пользовательской разметки;
- `.json`: сообщения и статистика обработки. поля верхнего уровня: `messages`, `warnings`, `files`, `duplicates`, `audio`. у сообщения: `id`, `date`, `sender`, `text`, `reply_to`, `reactions`.

даты остаются как в экспорте. вложения не копируются, пути к ним остаются относительно папки чата.

## что учитывать

переписка и аудио обрабатываются локально. приложение не отправляет их в API; интернет нужен для скачивания модели из Hugging Face. сам результат тоже содержит личную переписку. экспорты, медиа и результаты исключены из Git.

расшифровка может ошибаться на шуме и неразборчивой речи. фотографии не распознаются, из обычных видео речь не извлекается. нескачанные вложения остаются отметками, ошибки файлов попадают в предупреждения. ошибка загрузки модели останавливает обработку.

отмена ждёт завершения текущей расшифровки или загрузки модели. при отмене результат не записывается. большие чаты могут потребовать много памяти: страница HTML и сообщения результата хранятся в RAM.

## тесты

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
```

в тестах только вымышленные сообщения: страницы, ответы, дубли, медиа, реакции, отмена и сохранение. GitHub Actions запускает их на Windows/Linux с Python 3.12/3.13. распознавание в CI не запускается, ему нужна скачанная модель.

код парсера и CLI лежит в `parser.py`, окно в `gui.py`. отдельный FFmpeg устанавливать не нужно: аудио читает PyAV. для совместимости с faster-whisper ограничил его версию в `requirements-audio.txt`: в PyAV 19 удалили аргумент, который ещё использует faster-whisper 1.2.1 ([обсуждение](https://github.com/SYSTRAN/faster-whisper/issues/1589)).
